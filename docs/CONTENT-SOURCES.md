# ELSYSTAR content sources

This file records the public source pages used to seed verified catalog content. It is not a license or a substitute for editorial review.

## Official public sources used in beta.5

- `https://www.elsystar.com/` — company positioning, manufacturing scope, controllers, Megapolis overview and published contacts.
- `https://www.elsystar.com/production.html` — UK-4.1M and UK-2.5 technical characteristics, controller modes and Megapolis functionality.
- `https://www.elsystar.com/software.html` — Megapolis software architecture, subsystems, scalability and API positioning.
- `https://www.elsystar.com/support.html` — publicly listed software and technical-document downloads.
- `https://www.elsystar.com/price.html` — product/configuration names and composition only.

## Migration rules

1. Prices are not imported. The old page is treated as a configuration/source list, not as a current commercial price list.
2. Address, INN, KPP and OGRN are not invented when a verified source is unavailable.
3. Claims about customers or deployments are not promoted from old pages into current case studies without separate confirmation.
4. Demo projects remain explicitly marked as demo/modelled scenarios and are not used as proof of deployment.
5. Product images imported by beta.5 point only to official ELSYSTAR-hosted image URLs and replace only the exact temporary bootstrap media rows.
6. New editor-uploaded media and manually edited CMS content are never overwritten by the beta.5 bootstrap.
7. Document links are imported as public legacy materials. `legacy` means the current website exposes the file; it does not assert that the document is the latest legally or technically applicable revision.
8. A document year/version is retained as a version label. Do not invent an exact publication date when the source provides only a year or version.

## Editorial follow-up before production

- Confirm current certificate validity and replace/archive obsolete certificates as required.
- Confirm which legacy software downloads should remain public.
- Replace external legacy-hosted images with owned media storage when production storage is connected.
- Confirm the current legal address, working hours and corporate requisites before publishing them.
- Replace demo cases with verified projects only when project names, scope, dates and metrics are approved for publication.
