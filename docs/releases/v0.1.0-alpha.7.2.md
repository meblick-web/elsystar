# v0.1.0-alpha.7.2 — Guarded Prisma Push Hotfix

## Problem

Codespaces startup stopped on Prisma's interactive warning before adding the unique `(seriesId, version)` constraint to `Document`.

The warning is valid because a unique constraint cannot be created when duplicate non-null pairs already exist, but an interactive prompt breaks unattended Codespaces startup.

## Fix

Added `packages/database/scripts/codespaces-safe-push.mjs`.

Before allowing the known alpha.7 uniqueness upgrade it:

1. checks whether `Document.seriesId` already exists;
2. if it exists, searches for duplicate non-null `(seriesId, version)` pairs;
3. aborts without applying schema changes when duplicates are found;
4. checks whether the expected unique index already exists;
5. uses `--accept-data-loss` only for the known first-time uniqueness upgrade after duplicate preflight passes;
6. after the index exists, future startup returns to ordinary `prisma db push` without automatically accepting later risky schema changes.

Codespaces startup uses this guarded push and retains the existing timeout/logging behaviour.

CI additionally validates the guarded push script syntax with Node.js.
