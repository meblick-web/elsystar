# v0.1.0-alpha.7.4 — HTTP Admin Login Hotfix

## Problem

GitHub Codespaces reverse proxy continued to trigger Next.js `Invalid Server Actions request` for the admin login form despite explicit allowed origins.

## Fix

Admin authentication no longer depends on a Server Action:

- `/login` now submits a normal HTML POST form;
- new `POST /api/auth/login` route handler validates credentials;
- the existing signed HttpOnly admin session cookie is preserved;
- successful login redirects to `/` with HTTP 303;
- invalid credentials redirect to `/login?error=1`;
- the route-handler path bypasses the Server Action `Origin` / `X-Forwarded-Host` CSRF gate that is incompatible with the current Codespaces proxy path.

This is intentionally limited to authentication; existing server actions elsewhere remain unchanged.
