# v0.2.0-beta.3.1 — Codespaces Preview Recovery

## Причина

После перезапуска Codespace public/admin могли не появиться ни на одном forwarded port, если стартовый скрипт останавливался на временно недоступной PostgreSQL или на одном из CMS bootstrap-шагов до запуска Next.js.

## Исправлено

- старт preview сначала ждёт PostgreSQL до 60 секунд;
- временная недоступность БД больше не блокирует запуск web/admin процессов;
- ошибки development schema sync и content/SEO bootstrap выводятся как предупреждения и не гасят preview;
- public web и admin запускаются независимо: отказ одного контура не завершает второй;
- если не поднялся ни один контур, старт завершается ошибкой с автоматической диагностикой;
- диагностика показывает listeners/HTTP status для 6300, 6301, 16300, 16301 и последние строки ключевых логов;
- Prisma Client generation остаётся обязательным fatal gate;
- Codespaces search indexing остаётся выключенным;
- существующая схема public 6300 / admin 6301 и internal 16300 / 16301 сохраняется.

## Запуск

```bash
git pull && bash .devcontainer/start-preview.sh
```

В конце скрипт явно печатает `READY` или `FAILED` отдельно для public и admin.
