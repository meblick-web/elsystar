# v0.2.0-beta.1 — Security & Operations

Первый beta-этап после завершения alpha-линейки. Цель — не добавлять новые публичные функции, а зафиксировать server-side access control, защитить внешние точки входа и подготовить эксплуатационный контур перед SEO/production.

## RBAC

- Централизована матрица прав `ADMIN / EDITOR / SUPPORT / ANALYST`.
- Admin route guard блокирует доступ к разделам по роли.
- Изменяющие действия повторно проверяют роль на сервере.
- ADMIN: users/audit и полный доступ.
- EDITOR: CMS, каталог, solutions/projects, corporate, media, SEO, documentation.
- SUPPORT: leads + documentation.
- ANALYST: analytics.
- Отключение DB-пользователя или изменение роли инвалидирует текущую DB-backed session и требует повторного входа.

## Session hardening

- HMAC-SHA256 signed admin sessions.
- TTL уменьшен до 8 часов.
- HttpOnly + SameSite Strict + Priority High.
- HTTPS/Codespaces/production используют Secure `__Host-elsystar_admin_session`.
- Production требует `ADMIN_SESSION_SECRET` >= 32 chars.
- Failed login / bootstrap recovery login отражаются в AuditLog.

## Abuse protection

Добавлена PostgreSQL-модель `SecurityRateLimit` и DB-backed fixed-window limiter.

- Login: 5 / 15 min для hashed client + email.
- Leads: 5 / 10 min на client.
- Analytics ingestion: 300 / 10 min на client.
- Клиентский IP не сохраняется в plaintext rate-limit storage; ключ хэшируется/HMAC.
- Commercial form получил honeypot.
- Lead/analytics endpoints ограничивают content type, payload size и поля.

## Security headers

Public и Admin получают:

- CSP;
- `nosniff`;
- `X-Frame-Options: DENY`;
- strict referrer policy;
- restricted Permissions Policy;
- HSTS в production.

Admin также получает `Cache-Control: no-store`.

## Media / documents

Поскольку binary storage пока provider-neutral и реальный upload не подключён, beta.1 защищает metadata layer:

- только HTTP/HTTPS URL;
- запрет embedded credentials;
- MIME allowlist;
- safe filename normalization;
- file-size metadata cap 250 MiB;
- существующий SHA-256 для document versions сохраняется.

Binary MIME sniffing и provider ACL будут добавлены при подключении production storage.

## Operations

- `/api/health` для public и admin.
- PostgreSQL backup: `npm run db:backup`.
- Guarded restore: `ELSYSTAR_RESTORE_CONFIRM=YES npm run db:restore -- <backup.dump>`.
- Backup custom-format валидируется через `pg_restore --list` и сопровождается SHA-256 sidecar.
- Restore требует явного подтверждения и выполняется с `--exit-on-error`.
- Добавлен `npm run security:check` и production security preflight.
- Добавлен `docs/OPERATIONS.md`.

## CI

Pipeline проверяет:

1. install;
2. production dependency audit;
3. security preflight;
4. Prisma generation;
5. TypeScript;
6. production builds public/admin;
7. syntax security/backup/restore scripts;
8. Codespaces configuration and bootstraps.

## Что намеренно не входит

- SEO/indexing/structured data migration — следующий `beta.2`.
- реальный production storage/upload — выбирается вместе с hosting в production preparation;
- domain/SSL switch — только после beta.2 и final QA.
