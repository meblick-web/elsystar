# v0.1.0-alpha.7.1 — Codespaces Server Actions & Restart Hotfix

## Problem 1: Server Actions behind GitHub Codespaces

GitHub Codespaces exposes the applications through `*.app.github.dev` reverse-proxy URLs. Next.js Server Actions validate request origins as a CSRF protection measure. Without explicitly allowing the Codespaces proxy origin, form submissions such as admin login could fail with `Invalid Server Actions request` before application authentication logic was reached.

### Fix

Both Next.js applications now allow the Codespaces development origin:

- `apps/web/next.config.ts`
- `apps/admin/next.config.ts`

The configuration includes:

- `allowedDevOrigins: ["*.app.github.dev"]`
- `experimental.serverActions.allowedOrigins: ["*.app.github.dev"]`

This covers admin login and public Server Action forms while retaining Next.js origin validation for unrelated hosts.

## Problem 2: mixed-version preview after git pull

The previous Codespaces startup script skipped restarting a service when its port was already responsive. After `git pull`, this could leave an older Next.js process serving a newer working tree, including stale Server Action/Turbopack manifests.

### Fix

`.devcontainer/start-preview.sh` now:

1. stops the existing web/admin process groups;
2. falls back to cleaning stale Next.js processes when an old PID file is unavailable;
3. removes `apps/web/.next` and `apps/admin/.next` before restart;
4. regenerates Prisma Client;
5. synchronizes the development database schema;
6. starts both Next.js applications from the current repository revision;
7. refuses to start when a stale process still owns a preview port.

## Prisma startup visibility

Prisma generation and `db:push` previously redirected all output to log files, making a healthy operation look frozen in the terminal.

The startup script now:

- streams output to the terminal and log files simultaneously;
- shows an explicit completion marker for each step;
- applies a 180-second timeout per Prisma step;
- returns a clear failure when the timeout or command fails.

## Scope

This is an infrastructure hotfix on top of `v0.1.0-alpha.7 — Documentation & Software Center`. No product or documentation data model behavior was intentionally changed.
