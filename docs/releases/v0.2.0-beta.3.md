# v0.2.0-beta.3 — Release Candidate & Final QA

## Цель

Подготовить ELSYSTAR к первому реальному deployment без привязки к конкретному hosting provider.

## Реализовано

### Host-agnostic runtime
- production start public/admin теперь уважает переменную `PORT`;
- локальные default ports 6300/6301 сохранены;
- Codespaces development workflow не меняется.

### Guarded first production DB init
- добавлен `npm run db:init:production`;
- требуется явное `ELSYSTAR_PRODUCTION_INIT=YES`;
- скрипт разрешён только для полностью пустой PostgreSQL public schema;
- если таблицы уже существуют, скрипт останавливается без изменений;
- на чистой БД создаётся schema и выполняются существующие content/QA/SEO bootstraps;
- существующая production DB никогда не получает автоматический destructive push через этот сценарий.

### Runtime smoke gate
- добавлен `npm run smoke:production`;
- CI после production build реально запускает public и admin через `next start`;
- проверяются health endpoints и ключевые public routes;
- проверяются admin login/robots/health;
- тест не требует PostgreSQL и использует безопасные fallback/readiness states.

### Release preflight
- добавлен `npm run release:check`;
- проверяется синхронность версий web/admin/database;
- проверяются health/robots/sitemap/release scripts;
- проверяется поддержка host-provided `PORT`;
- preview credentials не должны попадать в public source;
- отсутствие Prisma migration history явно отражается предупреждением;
- неактивный `RU / EN` UI отражается предупреждением до полноценной локализации.

### Accessibility polish
- public и admin получили skip-navigation link;
- клавиатурный пользователь может перейти напрямую к основному содержимому;
- focus state видим и не меняет обычную компоновку.

### Documentation
- `docs/RELEASE-CHECKLIST.md` — единый host-agnostic checklist;
- зафиксированы обязательные production env, content/SEO gates, backup/rollback и ограничения первого DB init.

## Важное ограничение

Исторической Prisma migration chain пока нет, потому что проект до первого production deployment развивался через guarded development `db push`. `beta.3` решает безопасный **первый запуск на чистой БД**. Для дальнейших production schema changes потребуется отдельная reviewed migration chain.

## Не входит

- выбор hosting provider;
- подключение домена;
- реальная production PostgreSQL;
- включение поисковой индексации;
- полноценная английская локализация.
