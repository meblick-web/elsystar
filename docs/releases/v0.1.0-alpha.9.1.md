# v0.1.0-alpha.9.1 — Dense Technical Visual Refresh

## Goal

Rework the public visual layer after alpha.9 based on direct design feedback: reduce excessive whitespace, add a persistent traffic-engineering background motif, increase visual density and introduce realistic, fully-filled demo projects while the real project portfolio is still being prepared.

## Visual direction

- subtle semi-transparent road grids, lane markings, intersection geometry and ITS network lines across the whole public site;
- denser vertical rhythm and shorter section spacing;
- richer hero sections for catalog, support, solutions, contacts and FAQ;
- real photographic visual backgrounds used as atmosphere, with technical overlays kept subtle;
- denser cards, smaller gaps and more useful information above the fold;
- existing business logic and Prisma schema remain unchanged.

## Homepage

- hero now combines the controller illustration with an urban traffic image and network overlay;
- product cards use real CMS media when available;
- solution cards display imagery when available;
- featured project cards display images, metrics and demo status;
- sections reordered and tightened to reduce empty areas.

## Demo projects

When there are no published project records in CMS, the public site now shows clearly labeled demonstration cases for:

- Нальчик;
- Пятигорск;
- Минеральные Воды;
- Краснодар.

Each demo contains:

- full summary;
- task;
- proposed solution;
- modelled result;
- key metrics;
- cover image.

Demo pages explicitly state that the figures are illustrative and are not claims about a real ELSYSTAR deployment. As soon as real published projects exist in CMS, they replace the fallback demo portfolio automatically.

## Projects UX

- featured case with large image and metrics;
- dense project grid;
- explanatory project-data sidebar;
- richer project detail hero;
- explicit demo disclosure;
- commercial CTA for a similar project.

## Compatibility

- no database migration;
- no admin workflow changes;
- Codespaces workflow remains unchanged;
- CMS media and real project data always take priority over visual/demo fallbacks.
